# BEDMS Table Descriptions

| No | Table | Description |
| --- | --- | --- |
| 1 | Users | This collection stores authentication and authorization data for all system accounts, including email, password hash, Google login ID, display name, active status, and role (`student`, `manager`, `security`, `admin`). It is the root collection for login and RBAC. |
| 2 | Students | This collection stores the student profile linked 1-1 to a user account, including student code, personal information, major, cohort, student type, behavioral score, violation counters, and ban status. It is used for all dormitory operations related to residents. |
| 3 | Staffs | This collection stores staff profile data linked 1-1 to a user account, including staff code, personal information, phone number, gender, and position. It represents managers, security staff, and other dormitory employees. |
| 4 | Dorms | This collection stores top-level dormitory information such as dorm name, dorm code, total floors, total blocks, description, and active status. It is used as the parent entity for physical dorm structure management. |
| 5 | Blocks | This collection stores blocks/buildings/floors under a dorm, including block name, block code, floor metadata, gender type, room count, and active status. It organizes rooms inside a dormitory. |
| 6 | Rooms | This collection stores room information such as room number, room type, floor, bed capacity, available beds, semester price, student type, bathroom type, and room status. It is the main unit for accommodation allocation and billing. |
| 7 | Beds | This collection stores bed-level data inside rooms, including bed number, optional numeric bed ID, room reference, and occupancy status. It is used for precise assignment of students to specific beds. |
| 8 | BookingRequests | This collection stores room/bed booking requests submitted by students, including requested room, optional bed, semester, booking period, status, expiration, linked invoice, and review metadata. It supports the pre-contract reservation workflow. |
| 9 | Contracts | This collection stores confirmed accommodation contracts for students, including assigned room, assigned bed, semester, contract period, room price, contract file URL, signature date, and contract status. It represents an approved stay in the dormitory. |
| 10 | ContractExtensions | This collection stores student requests to extend existing contracts, including new end date, extension months, additional cost, approval status, and reviewer metadata. It supports contract renewal management. |
| 11 | RoomTransferRequests | This collection stores requests from students to move from one room to another, including current room, target room, reason, approval status, rejection reason, and review metadata. It supports room reassignment workflows. |
| 12 | Invoices | This collection stores monthly or period-based billing records for students, including invoice code, room, invoice month, fee breakdowns, total amount, payment status, due date, and creator staff. It is the main collection for financial receivables. |
| 13 | InvoiceLineItems | This collection stores detailed line items of an invoice, including item type, description, quantity, unit price, and calculated amount. It allows each invoice to be broken down into billable components such as room fee, electricity, water, and services. |
| 14 | Payments | This collection stores payment transactions for invoices, including transaction code, PayOS-related fields, payment amount, payment method, status, paid time, and transaction payload. It is used to track online and offline payment attempts and completions. |
| 15 | PricingConfigs | This collection stores pricing configuration records for utilities and service fees, including config type, unit price, measurement unit, effective period, active status, and creator staff. It supports configurable billing rules over time. |
| 16 | UtilityReadings | This collection stores monthly room utility meter readings, including previous and current electricity/water readings, calculated consumption, room reference, recorded month, and recorder staff. It provides the consumption basis for invoice generation. |
| 17 | EquipmentCategories | This collection stores master categories for equipment, such as furniture or appliances, including category name and description. It provides logical grouping for equipment templates. |
| 18 | EquipmentTemplates | This collection stores reusable equipment master data, including category, equipment name, brand, model, specifications, expected lifespan, unit price, and active status. It defines the standard types of equipment that can be assigned to rooms. |
| 19 | RoomEquipments | This collection stores actual equipment assigned to specific rooms, including equipment code, template reference, quantity, status, condition notes, maintenance dates, warranty dates, and assignment date. It represents the live room asset inventory. |
| 20 | RoomTypeEquipmentConfigs | This collection stores standard equipment requirements by room type, including room type, equipment template, standard quantity, and mandatory flag. It defines what equipment a room type is expected to have. |
| 21 | EquipmentHistories | This collection stores audit history for room equipment changes, including action type, old/new status, old/new room, notes, performer staff, and action time. It is used for traceability of equipment movement and condition changes. |
| 22 | RoomInspections | This collection stores room inspection records, including room, optional contract, inspection type, cleanliness status, equipment status, notes, maintenance needs, photos, inspector staff, and inspection time. It supports check-in, check-out, periodic, and complaint inspections. |
| 23 | InspectionEquipmentDetails | This collection stores item-level inspection results for specific room equipment during an inspection, including inspection reference, equipment reference, condition at inspection, notes, and photo. It provides detailed evidence for room inspection outcomes. |
| 24 | ViolationReports | This collection stores reports of student rule violations, including report code, reported student, reporter, reporter type, violation type, description, evidence, date, location, status, and review metadata. It supports disciplinary case management. |
| 25 | Penalties | This collection stores disciplinary penalties assigned to students, including linked violation report, penalty type, deducted points, reason, semester, issuing staff, and issue time. It is used to enforce dormitory rules and update conduct scoring. |
| 26 | BehavioralScoreHistories | This collection stores the history of behavioral score changes for students, including change type, points changed, score before/after, reason, semester, creator staff, and creation time. It provides an audit trail for conduct score adjustments. |
| 27 | MaintenanceRequests | This collection stores maintenance or repair requests submitted by students, including request code, room, optional equipment, issue type, priority, description, evidence, workflow status, technician details, schedule, completion notes, and reviewer metadata. It is the main workflow collection for facility maintenance. |
| 28 | MaintenanceFeedbacks | This collection stores student feedback for completed maintenance requests, including linked request, student, rating, completion status, comments, after-repair images, and submission time. It is used to assess maintenance quality and completion. |
| 29 | VisitorRequests | This collection stores requests for visitors to enter the dormitory, including request code, requesting user, visit date, visit time range, purpose, status, rejection reason, and reviewer metadata. It supports the visitor approval process. |
| 30 | Visitors | This collection stores visitor identity information attached to a visitor request, including full name, citizen ID, phone number, relationship to resident, and optional custom relationship text. It represents the actual people expected to visit. |
| 31 | VisitorCheckins | This collection stores visitor entry and exit logs, including visitor request, visitor, check-in time, check-out time, the user who checked them in/out, and notes. It supports security control and visitor tracking. |
| 32 | Notifications | This collection stores in-app notifications sent to users, including title, message, type, category, read status, related object ID, and creation time. It is used for system alerts across payment, booking, maintenance, violations, visitors, equipment, and chat. |
| 33 | ChatConversations | This collection stores chat session metadata between a student and a staff user, including participant references, conversation status, unread counters, and last message timestamp. It is the parent container for message threads. |
| 34 | ChatMessages | This collection stores individual chat messages inside conversations, including sender, sender type, message text, optional attachment URL, read status, and sent time. It supports direct communication between students and dormitory staff. |
| 35 | News | This collection stores news posts and announcements, including title, content, thumbnail, category, publication status, published time, and creator staff. It is used to publish dormitory information to users. |
| 36 | SystemConfigs | This collection stores configurable system settings as key-value pairs, including config key, config value, description, value type, updater staff, and update time. It supports runtime configuration without hardcoding values in source code. |
